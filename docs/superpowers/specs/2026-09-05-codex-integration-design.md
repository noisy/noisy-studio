# Codex integration and agent-neutral onboarding

## Scope and acceptance

Users install a Codex plugin, select their existing Noisy Studio daemon,
review its hooks, and complete a spoken round trip. Two Codex sessions and
a Claude session can share a working directory without sharing identity.
The dashboard describes the actual agent rather than calling every agent
Claude. OpenAI speech providers, releases, and changes to the live stream
configuration are outside this task.

Work is isolated on `feat/codex-integration`, based on `v3-desktop` at
`0a53f50`, in `../noisy-studio-codex`. Stream-day-6 Claude supervises design
and reviews the final diff before anything merges. The original checkout
and its uncommitted changes belong to that session.

## Architecture

Use the existing daemon, MCP server, and shared hook scripts. Add Codex
packaging and small host adapters; do not create a second voice service or
fork the scripts. Keep the Claude plugin installation working.

### Identity is supplied per call

Codex hook input includes `session_id`. The Codex PreToolUse adapter
registers that session and replaces `agent_id` on identity-sensitive MCP
calls through `hookSpecificOutput.updatedInput`. It unconditionally
overwrites any value generated by the model. Identity is never inferred
from the working directory or a shared MCP process environment.

The shared MCP tools accept an optional `agent_id`. A supplied, nonempty
identifier selects that agent and disables the legacy cwd fallback for
that call. Calls with the argument omitted preserve the existing Claude
resolution order: explicit environment, Claude session id, then cwd map.
The Codex adapter fails closed for an identity-sensitive call if session
identity is missing: block the tool, surface a hook warning, and send a
best-effort error event to the daemon. Do not invent a default session.

The adapter must match Codex-normalized MCP names as well as namespaced
plugin names without modifying unrelated tools. Registration, activity,
inbound draining, and speaking use exactly the same identity. Concurrent
tool calls cannot change process-global identity.

### Lifecycle

SessionStart and UserPromptSubmit register the agent and report activity.
PreToolUse reports activity and supplies speech identity. PostToolUse
drains transcripts into model context using the existing output contract.
Stop uses the existing script synchronously and preserves stderr plus exit
code 2 for continuation. There is no claim of an `asyncRewake` equivalent.

The default Stop listening window is 3600 seconds, with a 3630-second hook
timeout. Document that the turn remains open while waiting; expose a shorter
window and a way to disable idle listening without losing mid-task input.
Daemon absence must return promptly and quietly for observation hooks;
failed speech must be visible. Only one listener consumes a session queue.

Investigate `codex queue` on an isolated idle session before considering it
as a replacement. An observed wake is evidence for a future bridge, not
permission to introduce another long-lived service into this implementation.

### Configuration and packaging

Ship a dedicated Codex manifest, MCP configuration, setup/conversation
skill, and hook definitions alongside the Claude distribution. Reuse the
canonical hook scripts, with packaging paths verified against the real
Codex loader rather than assuming Claude plugin semantics.

One selected daemon endpoint serves both MCP and hooks. Support the app
(9765), Docker (8765), development (7765), and arbitrary user ports; do not
embed the current development endpoint in distributed files. Selection must
be explicit when more than one daemon is running. Never silently switch
between available daemons.

Installation and removal are idempotent and preserve unrelated hooks, MCP
servers, and settings. Invalid existing configuration stops installation
without replacing it. Do not manufacture hook trust or weaken permissions.
The setup skill explains exactly what the user reviews through `/hooks`.
Use isolated temporary configuration for installer/plugin verification.

### Agent-neutral presentation

Audit user-visible Claude assumptions in chat headers, statuses, tooltips,
activity, onboarding, and speech events. Register generic agent display
metadata and use it for titles; use “Agent” when metadata is unavailable.
Named speakers retain their explicitly configured labels. No Codex-vs-Claude
switch statement in the dashboard.

Existing persisted history and clients must continue working. Legacy wire
fields or role values may remain behind a compatibility boundary where
renaming them would break history; they must not dictate visible labels.
Record remaining compatibility names in the implementation report rather
than silently treating them as newly generic. Update affected component
stories and tests; preserve the current visual design.

## Verification

- Baseline: 181 unit tests pass on `v3-desktop` before changes.
- Interleave two Codex calls and one legacy Claude call through one MCP
  process with the same cwd; inspect actual outgoing daemon request bodies.
- Supply a forged model `agent_id`; the hook replaces it. Missing session
  input blocks the call, emits a warning, and attempts a daemon error event.
- Exercise the shared hook entrypoints with fake daemon responses: queued
  speech, empty queue, unavailable daemon, Stop continuation and timeout.
- Install twice and remove in a temporary Codex home containing unrelated
  hooks and MCP entries. Verify preservation and reversibility.
- Load packaged manifests using the installed Codex CLI in an isolated
  home. Record any surface/version limitations honestly.
- Render existing chat components with arbitrary agent names, absent
  metadata, old history, and named speakers; run frontend tests, typecheck,
  and build for changed UI paths.
- Run all Python unit tests and relevant package/skill validation; send
  the final diff and evidence to the supervisor before merge.

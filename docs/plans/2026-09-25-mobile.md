# Mobile companion implementation

Issue #170. Build in `mobile/` to version the client beside the daemon contract.
Alternatives: a separate repository increases schema drift; a responsive web view
cannot supply the requested native shell. Flutter provides both native targets and
Widgetbook web previews from the same components.

The first version selects conversations and controls the DESKTOP microphone and
speaker. Phone audio and pairing remain #124. Fixture mode is the default; explicit
address connection does not change daemon bind settings. Screens: Agents, Talk,
Recent, Settings. Agent IDs remain internal; names fall back to New conversation.

- [x] Fixture models, reusable screens and Widgetbook state/device/theme catalog.
- [x] Typed HTTP/WS client, snapshot parser and cancellable PTT lease owner.
- [x] Native shell, focused transport/lifecycle and screen tests.
- [x] Scoped Android CI, manual iOS cloud-signing workflow and setup docs.

Reference inspection: Bucky shell d66d763 and its generic CI conventions. No license
was present in that private repository. The owner explicitly authorized borrowing;
implementation here is original, reusing conventions rather than product code,
identifiers, assets or signing material. No Firebase or Bucky-specific features.
